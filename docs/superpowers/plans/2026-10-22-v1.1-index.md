## 1. Parties and matchmaking (v1.1.0, shipped)

- **Ledger:** per-pot fee, a prize payout namespace that never collides with brands' `Reward` claims.
- **`party`:** groups, open/closed, leader actions, chat/data messages, `Lock` for tournaments.
- **`matchmaking`:** queues (teams, FFA, asymmetric, staked/free/ranked, `Prepare`, `Concurrent`,
  `AllowOffline`), tickets with idempotency, matcher, formation with stake holds, results and
  payouts, OpenSkill ratings, direct matches (`Create`), cancel/timeouts, history, metrics.
- **Admin:** matches (cancel, report result), queues, ratings, parties (disband).

## 2. Leaderboards (v1.2.0, future)

- **First task, carried over from v1.1:** same-match duplicate `Finish`/`Cancel` calls wait on the
  match row lock while holding a pool connection outside the money-step slots; enough of them at
  once can still starve the Postgres pool. Take a slot around `Finish`/`Cancel`'s transaction, or
  set a `lock_timeout` in `lockWait`. Other deferred v1.1 minors: see the v1.1 final review notes.

- **`leaderboard`:** boards created in Go or the console. Config: sort, operator
  (best/set/incr/decr), owner (user or party), optional reset schedule.
- **Seasons:** archived standings per season. Scores are `int64` + subscore. Only game code or an
  admin writes scores.
- **Reads:** top N, around a player, given owners.
- **Admin:** create/edit, standings, set/remove a record with a reason.
- **Consumes:** `App.Loop` (resets), `party` (party owners).
- **Produces for P3/P4:** board/season API, `Submit`, rank queries.

## 3. Tournaments (v1.3.0, future)

- **Admin additions (`admin`):** page-level actions ("New …") and a repeating-rows input type
  (prize tables, tiers).
- **`tournament`:**
  - Score format: on a P2 board scoped to a time window.
  - Bracket format: single/double elimination, round robin, Swiss. Seeding, byes.
  - Entrants are players or parties (rosters locked with `party.Lock`).
- **Money:** entry fees held with `HoldPot`, a pot per occurrence; prize tables (shares or fixed
  amounts, ties); guarantee and added prizes via `RewardPrize`; a second admin's approval above
  `ApproveAbove`, whoever creates the tournament.
- **Results:**
  - Matches come from `matchmaking.Create` on the tournament's own queue; `OnFinish` advances the
    bracket.
  - Leaders report results; disagreements go to a disputes list.
  - Default when a round deadline passes.
- **Admin:** create/edit, approve funding, bracket/standings, report, disputes, cancel (refund).
- **Consumes:** P1 (`Create`, `OnFinish`, `SettlePotFee`/`SettlePoolFee`, `RewardPrize`,
  `party.Lock`), P2 (boards).

## 4. Leagues (v1.4.0, future)

- **Divisions mode:** tiers × groups of N, promotion/relegation of top X / bottom Y; group
  standings 3/1/0 or season score.
- **Reset-and-place mode:** soft or full reset of the rating or score, K placement results, tier
  thresholds.
- **Pairing:** the league queue pairs within a tier (default) via `QueueConfig.Prepare`.
- **Seasons:** optional entry fee per season; season prizes with the same rules and approval as
  tournaments; archived standings.
- **RPCs:** `league.me`, `league.standings`. Admin: create, tiers, seasons, standings.
- **Consumes:** P1 (ratings, `Prepare`), P2 (season boards), P3 (prize payout and approval code).
