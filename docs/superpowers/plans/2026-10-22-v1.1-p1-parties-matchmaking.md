# v1.1 Plan 1: Ledger Additions, Parties, Matchmaking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the foundation of v1.1: fee-parametrised pots and prize payouts in the ledger, the `party` module, and the `matchmaking` module (queues, tickets, matcher, staked/free/ranked matches, OpenSkill ratings, direct matches, admin pages).

**Architecture:** Additive only. The ledger gains `SettlePotFee`/`SettlePoolFee`/`RewardPrize` (old calls delegate). `app` gains `Loop` for the matcher tick; `apptest.Transport` gains `SetOnline`. `party` and `matchmaking` are opt-in modules like `fairness`: own migrations, sqlc, RPCs, reconcilers. Matching is a pure function over tickets, wrapped by a per-queue advisory-locked tick. Matches follow "record first, then money".

**Tech Stack:** Go 1.27, pgx/v5, sqlc, goose, TigerBeetle 0.16.46, Postgres 17.

**Spec:** `docs/superpowers/specs/2026-10-22-multiplayer-design.md` (sections Policy, Packages, 1 Parties, 2 Matchmaking, 6 Admin as it concerns matches/parties, 7). Later plans: P2 leaderboards, P3 tournaments + admin page actions/repeating rows, P4 leagues, P5 docs/release.

## Global Constraints

- v1.0.0 is tagged: never edit a committed migration, never break an exported API. Everything here is additive.
- Every product rule is config with a default (CLAUDE.md "No imposed policy"); invariants (money, identity, idempotency, audit) are not.
- Money is `int64` minor units; drivers refuse overdrafts; no app-side balance checks.
- Transfer IDs deterministic. New platform game ID: `matchmaking.Game ledger.Game = 1`, never changed; document the platform ID list next to the namespaces in `ledger/ledger.go`.
- Every ledger change passes `ledgertest` on Postgres **and** TigerBeetle; never weaken a case.
- sqlc for every query; generated code in `<pkg>/internal/store`; add each package to `sqlc.yaml` (schema list includes `db/migrations` for `users`, plus `party/migrations` for matchmaking).
- User ID only from the RPC handler's `userID`. Every money-moving RPC carries `idem_key` (≤ 64 bytes).
- Ratings are `float64` (not money). No `math/rand` anywhere in these packages.
- Client error codes: party 1020–1029, matchmaking 1030–1039.
- Every push: `realtime.PublishJSON(ctx, a.Realtime, realtime.UserChannel(u), map/struct with "type")`.
- CHANGELOG.md: each task adds its Added/Upgrade lines under `## Unreleased`.

## Review Focus

1. A client retries `match.queue` with the same `idem_key` after its ticket became a match → gets that match, no second ticket, no second hold (Task 7).
2. Two app instances tick the same queue at once → no player in two matches, no ticket used twice (Task 8: two concurrent `MatchNow`).
3. A party member leaves while the party's ticket waits → ticket removed and pushed; with stakes, one broke member drops the whole party, the other side is re-queued with its original `queued_at` (Tasks 7, 8).
4. `Finish` twice with a different result → error, money and ratings applied once (Task 9).
5. Crash after a match row commits but before holds/OnMatch → `ReconcileNow` completes it; a match past `MatchTimeout` is cancelled and every hold refunded (Tasks 8, 9).

### Task 4: OpenSkill ratings (pure)

**Files:**
- Create: `matchmaking/openskill.go`, `matchmaking/openskill_test.go`

**Interfaces:**
- Produces:
  ```go
  type Rating struct{ Mu, Sigma float64 }
  func DefaultRating() Rating                          // {25, 25.0/3}
  func (r Rating) Ordinal() float64                    // Mu - 3*Sigma
  func rate(teams [][]Rating, ranks []int) [][]Rating  // Plackett-Luce, beta = 25/6, kappa = 1e-4; ranks: lower is better, ties equal
  ```
  Algorithm (Weng-Lin PL, as openskill): per team i: `mu_i = Σmu`, `s2_i = Σsigma²`; `c = sqrt(Σ_i (s2_i + beta²))`; `e_i = exp(mu_i/c)`; `sumQ_q = Σ_{i: rank_i >= rank_q} e_i`; `A_q = #teams with rank_q`. For team i, over q with `rank_q <= rank_i`, `p = e_i/sumQ_q`: `om += ([i==q] - p)/A_q`, `de += p(1-p)/A_q`. `omega = s2_i/c·om`; `delta = (sqrt(s2_i)/c)·s2_i/c²·de`. Player j: `mu += sigma_j²/s2_i·omega`; `sigma = sqrt(sigma_j²·max(1 - sigma_j²/s2_i·delta, kappa))`.

### Task 6: Matcher (pure)

**Files:**
- Create: `matchmaking/matcher.go`, `matchmaking/matcher_test.go`

**Interfaces:**
- Produces: `func form(q *Queue, tickets []Ticket, now time.Time) []formed` with `type formed struct{ Tickets []int64; Teams [][]int64 /* user IDs per team */ }`. Tickets already filtered to the queue and sorted by `QueuedAt`, ties by ID.
- Algorithm (spec §2 Matching): oldest unused ticket is the anchor; candidates = unused tickets with the anchor's currency, stake, equal `Properties` and `Server`, every `Numbers` key within `Diff + Widen*(anchorWait/Every)`, ranked: `|Rating - anchor.Rating| <= RatingWindow + RatingWiden*(anchorWait/10s)`, and `Compatible(x, y)` for every pair in the group. Fill teams with whole tickets (unit size = len(Users)), oldest first; a unit goes to the team with the most room it fits in (ranked: the team with the lowest summed rating that fits). Form when every team is at Max; or, once `now - anchor.QueuedAt >= FillAfter`, when every team is ≥ Min. FFA: teams are one-player each, count between FFA.Min and FFA.Max. Unformed anchors stay; continue with the next unused anchor. `// ponytail: O(n²) per queue per tick; bucket by properties if a queue outgrows it.`

### Task 8: Tick, formation, holds, reconcile

**Files:**
- Create: `matchmaking/formation.go`, `matchmaking/formation_test.go`

**Interfaces:**
- Produces: `func (s *Service) MatchNow(ctx) error` (one tick of every queue; tests call it), `func (s *Service) Reconcile(ctx)`, `func (s *Service) Get(ctx, id int64) (Match, error)`.
- Tick per queue, in one transaction under `pg_try_advisory_xact_lock(hashtext('mm:'+queue))` (skip queue if not acquired): drop expired tickets (`reason:"expired"`) and, unless `AllowOffline`, tickets with any user missing from `Realtime.Online` (`reason:"offline"`); load the rest; `form`; for each formed group delete its tickets, insert `mm_matches` (`forming`, `deadline = now + MatchTimeout`, fee_bp) and `mm_match_players` (rating snapshot), point `mm_requests` at the match. Commit, then `advance(match)` for each.
- `advance` (idempotent, also used by Reconcile for `forming`): staked → `HoldPot(Game, c, PotEntry{ID: player.EntryID, UserID, Amount: Stake})` per player. `ErrInsufficientFunds`/`ErrAlreadyFailed` for anyone → `VoidPot` all entries, match `cancelled` (reason `insufficient_funds`), short units get `match.ticket_removed {reason:"insufficient_funds"}`, other units re-inserted as tickets with their original `queued_at` (from Create: no re-queue). Other error → leave `forming`. Then `OnMatch` (error → cancel with refund, reason `on_match`), then `running` and push `{"type":"match.found",match}` to every player.
